# SSH integration

The `ssh` integration exposes approved remote commands for configured OpenSSH hosts, a local host-list action, and a `close` action that stops this process's shared master for a host. Remote commands require explicit tool approval and run outside the workspace sandbox, with `BatchMode`, bounded deadlines, capped streaming output, and a shared ControlMaster socket under Dial's user directory (or a private short-path fallback). The master persists for `ControlPersist=3600` seconds after last use and is closed at exit. Before the first command to a host, Dial probes its OS and shell once and caches the result under `<DIAL_HOME>/ssh/hosts`; `hosts` lists those labels (for example `linux/bash`) and the open masters. Hosts with an enabled POSIX compat layer run commands through that shell. Host aliases are interpreted by OpenSSH, so normal `~/.ssh/config` settings apply. `ssh://host/path` supports bounded remote reads, writes (atomic replacement), and grep; each remote operation requires approval and files are limited to 1 MiB. URL transfers are refused on Windows hosts without a POSIX shell. The `ssh://` scheme supports absolute paths and `~/` paths; URL query strings and fragments are rejected.

Enable or disable the `ssh` tool through the `integrations` configuration list. SSH host-key policy defaults to `accept-new`; pre-populate `known_hosts` and configure OpenSSH when stricter policy is required. The host-discovery parser lists concrete aliases from `~/.ssh/config` and included files; OpenSSH remains authoritative for effective connection configuration.
